# Claude 홀덤 테이블

2~6명이 한 테이블에 앉는 노리밋 텍사스 홀덤 웹게임. 혼자서 Claude · AI 플레이어와 두거나, 친구들과 각자 폰으로 들어와 같이 둔다.

- 시작 칩 각자 2,000 (100BB), 블라인드 10/20부터 10핸드마다 오름, 한 명 남을 때까지 (토너먼트)
- AI 플레이어는 GTO 근사 엔진(`gto.js`)으로 둔다
- Claude 자리는 claude.ai 아티팩트로 열면 GTO 엔진의 조언을 받아 Claude가 직접 판단한다. 그 밖의 곳(로컬, GitHub Pages)에서는 GTO 엔진이 대신 둔다
- 모든 AI는 자기 카드와 공개된 정보만 보고 판단한다
- 소리와 움직임: 카드를 나눠 주고 뒤집는 소리, 체크(테이블 두드림) · 벳 · 콜(칩) · 레이즈 · 올인(칩 쏟아짐) · 폴드, 내 차례 알림, 시간이 얼마 안 남으면 째깍, 팟을 따면 · 탈락하면 나는 소리. 위 막대의 스피커 버튼으로 끄고 켠다 (기억한다). 브라우저 규칙 때문에 화면을 한 번 누른 뒤부터 소리가 난다

## 소리 · 움직임

| 일 | 움직임 | 소리 |
|---|---|---|
| 새 핸드 | 딜러 버튼에서 각 자리로 한 장씩 두 바퀴 날아간다 (모두 뒷면, 내 카드는 도착하면 뒤집힌다) · 블라인드 칩 | 카드마다 `deal` · 블라인드 `chip` |
| 체크 | 베팅 자리에 두드린 자국 | `check` |
| 벳 · 콜 · 레이즈 | 칩이 자리에서 베팅 자리로 (금액은 칩이 도착하면) | 벳 `chip` · 콜 `call` · 레이즈 `raise` |
| 올인 | 명패가 잠깐 빛난다 | `allin` |
| 폴드 | 카드가 가운데로 미끄러지며 사라진다 | `fold` |
| 베팅 라운드 끝 | 모든 베팅이 팟으로 (받지 않은 몫은 자기 자리로) | |
| 플롭 · 턴 · 리버 | 뒷면으로 놓였다가 한 장씩 뒤집힌다 | 장마다 `flip` |
| 쇼다운 · 올인 공개 | 남의 카드가 뒤집힌다 | `flip` |
| 핸드 끝 | 팟마다 따로(사이드 팟 포함, 나눔이면 각자에게) 금액이 적힌 칩이 이긴 사람에게 · 이긴 다섯 장이 들린다 | 내가 따면 `win`, 아니면 `chip` |
| 탈락 | | `bust` |
| 내 차례 | 차례인 명패: 친구와 하기의 사람 차례는 남은 시간 링, 시간 제한이 없는 차례는 은은하게 숨쉰다. 마지막 10초는 링이 빨개지고 깜빡인다 | 차례마다 한 번 `turn`, 내 차례 마지막 10초 동안 초마다 `tick` |

- 무엇이 일어났는지는 그린 화면을 직전 화면과 비교해서 안다 (새 행동 · 스트리트 · 단계 · 결과). 그래서 혼자 하기 · 방장 · 손님에서 똑같고, 손님도 받은 화면(남의 카드는 뒷면)만 쓴다. 처음 그릴 때 · 이어하기 · 새로고침 · 다시 연결될 때는 지난 일을 다시 틀지 않는다
- 움직임은 테이블 위에 잠깐 띄우는 복제 카드 · 칩일 뿐이다(누르기를 가로채지 않음). 진짜 화면은 그 아래 이미 맞게 그려져 있고 게임 진행 · 타이머 · 입력 · 통신은 움직임을 기다리지 않는다. 새 핸드 · 화면 크기나 방향이 바뀔 때 · 창이 열릴 때 · 다른 탭으로 갈 때 · 빨리 감기에서는 지운다 (빨리 감기는 소리도 없이)
- 기기 설정의 "동작 줄이기"(prefers-reduced-motion)에서는 움직이지 않고 바로 바뀐다. 소리는 스피커 버튼을 따른다

## 친구와 하기 (각자 폰으로)

GitHub 주소 https://swlee3286.github.io/holdem/ 에서 연다. (claude.ai 아티팩트 안에서는 외부 연결이 막혀 있어 혼자 하기만 된다.)

**방 만들기 (방장)**
1. 처음 창에서 `친구와 하기` → 이름을 적고 `방 만들기`
2. 큰 글씨로 나오는 방 코드(5자리)를 알려 주거나 `공유`(또는 `링크 복사`)로 참가 링크 `…/holdem/#join-코드`를 보낸다
3. 인원(2~6명)을 고른다. 친구가 들어오면 `시작`. 빈 자리는 AI(GTO 엔진)가 앉는다

**참가하기 (손님)**
- 받은 링크를 열고 이름만 적으면 들어간다. 또는 `친구와 하기` → 코드 5자리 입력 → `참가`
- 방장이 시작하면 카드가 나온다. 내 자리는 늘 화면 아래 가운데

**알아 둘 것**
- 같은 와이파이가 아니어도 된다 (WebRTC로 기기끼리 직접 연결하고, 연결을 이어 주는 데만 PeerJS 공개 서버를 쓴다)
- 일부 회사·학교 와이파이나 일부 모바일 데이터처럼 엄격한 네트워크에서는 연결이 안 될 수 있다. 그때는 와이파이 ↔ 모바일 데이터를 바꿔 본다
- **방장 기기가 딜러다.** 진짜 게임은 방장 브라우저에서 돌아가므로 게임이 끝날 때까지 방장은 화면을 켜 두어야 한다 (지원하는 브라우저에서는 화면 꺼짐을 막는다). 방장이 새로고침하면 같은 코드로 다시 열고 하던 핸드를 잇는다 (방장 폰의 네트워크가 갑자기 끊겼던 경우에는 연결 서버가 예전 연결을 정리할 때까지 1~2분 걸릴 수 있다). 같은 브라우저의 다른 탭에서는 그 방을 열지 않는다. 방장이 나가면 손님 화면에 "방장이 나갔어요"가 뜨고, 방장이 돌아오면(20분 안) 자동으로 이어진다
- 사람 차례에는 30초 제한이 있다. 시간이 지나면 체크(못 하면 폴드)
- 손님 연결이 끊기면(창을 닫거나 폰이 잠들거나 네트워크가 끊기면) 그 사람 차례에 15초까지 기다렸다가 AI가 대신 두고, 같은 링크로 다시 들어오면 자리를 되찾는다. 시작 전 로비에서 끊긴 손님도 자리가 남아 있다 (방장은 `내보내기`로 뺄 수 있다)
- 자리는 방장이 그 방에서 처음 앉힐 때 준 비밀값으로 알아본다. 비밀값은 그 방에만 쓰고, 다시 들어올 때는 비밀값 대신 서로 증명(HMAC)만 주고받아 방장과 손님이 서로를 확인한다 (방장이 새로고침하는 사이 누가 방 코드를 가로채도 자리를 빼앗을 수 없다)
- 이름 `나` · `방장`은 화면에서 헷갈려 손님이 쓰면 뒤에 숫자가 붙는다
- 핸드가 끝나면 5초 뒤 다음 핸드가 자동으로 시작된다 (방장은 `다음 핸드`로 바로). 탈락해도 계속 지켜볼 수 있고, 매치가 끝나면 모두에게 순위가 나오며 방장이 `다시 하기`로 같은 방에서 새 게임을 연다
- 손님에게는 그 자리용으로 걸러진 화면만 간다 (남의 카드는 공개될 때만). 다만 방장 기기는 딜러라서 모든 카드를 갖고 있다 — 믿을 수 있는 친구끼리 즐기는 용도다
- GTO 힌트는 누구나 자기 자리에 대해서만 켤 수 있다

## 실행

빌드 과정이 없다. 폴더를 그대로 정적 서버로 연다.

```
python3 -m http.server 8765
```

브라우저에서 http://localhost:8765

GitHub Pages: 저장소 Settings → Pages에서 배포할 브랜치(이 저장소는 `gh-pages`)와 폴더 `/ (root)`를 지정하면 `index.html`이 열린다. GitHub Pages는 HTTPS라서 친구와 하기(WebRTC)가 된다.

시험용 주소 파라미터 (index.html):

| 파라미터 | 뜻 |
|---|---|
| `?net=local` | PeerJS 대신 BroadcastChannel — 같은 브라우저의 탭끼리 친구와 하기 (테스트 · 한 기기에서 해 보기). 탭마다 다른 손님 |
| `?peerHost=&peerPort=&peerPath=&peerSecure=0` | PeerJS 시그널링 서버를 바꾼다 (로컬 테스트 서버 등). `localhost` · `127.0.0.1`에서 열었을 때만 쓰고, 그 밖의 주소(GitHub Pages)에서는 무시한다. 참가 링크에도 localhost에서만 따라붙는다 |
| `?turnSec=30` · `?nextSec=5` | 방장 쪽: 차례 제한 시간 · 다음 핸드까지 초 |

### 친구와 하기 프로토콜 (버전 2, JSON 문자열)

- 처음 앉기: 손님 `hello {v, name}` → 방장 `welcome {seat, gid, secret}`. `gid`는 자리 표시, `secret`은 그 자리 비밀값 (방장이 만들고 이 손님에게 이 한 번만 보낸다). 손님은 방 코드별로 기억한다 (이 탭: sessionStorage, 창을 닫았다 열 때: localStorage)
- 자리 되찾기: 손님 `hello {v, name, gid, nonce}` → 방장 `auth {nonce, proof}` → 손님은 방장 증명을 확인한 뒤에만 `auth {proof}` → 방장 `welcome {seat, gid}`. 증명 = HMAC-SHA256(secret, 방향 · gid · 두 nonce). 방장 증명이 틀리면 손님은 그 연결을 버리고 다시 붙는다. welcome 전에는 lobby · state를 받지 않는다. 방장이 모르는 gid는 새 손님으로 본다 (시작 전 로비에서 빠진 손님). 진짜 방장은 시작한 뒤에는 새 자리를 주지 않으므로, 시작한 방의 자리를 가진 손님에게 증명 대신 새 자리(secret)를 주는 곳도 가짜 방장으로 보고 자리 기억을 덮어쓰지 않는다
- 손님 → 방장 (확인 뒤): `act {hand, n, type, to}` (n = 손님이 본 행동 수. 늦거나 차례가 아니거나 규칙에 안 맞으면 무시) · `ping` (3초마다) · `leave` (스스로 나감: 시작 전이면 자리를 비운다)
- 방장 → 손님: `lobby {code, players, seats, started}` · `state {view}` · `error {msg}` · `pong` · `bye`
- 방장은 확인(hello · auth)을 마치지 않은 연결에는 답하지 않고 8초 뒤 끊는다. 한꺼번에 받는 연결은 12개까지
- `view`는 한 자리용: 공개 정보 + 그 자리 카드 + 공개된(shown) 카드, 그 자리 차례일 때 가능한 행동, 남은 시간. 덱과 남의 카드는 넣지 않는다. 핸드 기록은 손님 기기가 view의 행동 목록으로 직접 만든다 (HTML을 주고받지 않는다)
- 10초 동안 소식이 없으면 끊긴 것으로 본다. 모든 메시지는 모양과 크기를 검사하고 틀리면 버린다

## GTO 근사 AI

솔버로 균형점을 계산하지는 않는다. 알려진 GTO 범위와 원칙을 규칙으로 옮긴 근사치다.

- 프리플롭: 포지션별 레인지 표(혼합 빈도 포함), 오픈·3벳·4벳·스퀴즈·림프 대응, 13BB 이하 올인-폴드
- 레인지 추적: 각 플레이어의 가능한 패 1,326가지를 행동마다 같은 모델의 확률로 좁힌다 (사람의 예상 밖 플레이에 대비해 바닥값을 둔다)
- 플롭 이후: 최소 방어 비율(MDF), 벳 크기에 맞춘 밸류 대 블러프 비율, 레인지 우위에 따른 c벳 빈도와 보드 질감에 따른 벳 크기, SPR에 따른 올인
- 결정은 행동별 비율(예: 폴드 20% · 콜 55% · 레이즈 25%)로 만들고 그 비율대로 고른다. 화면의 "GTO 힌트"와 Claude에게 주는 조언이 이 비율이다
